# Hekus DoorPhone Integration for Home Assistant

[![hacs_badge](https://img.shields.io/badge/HACS-Custom-41BDF5.svg)](https://github.com/hacs/integration)

Интеграция для управления домофонами Ufanet через Home Assistant. 
Интеграция использует ["Умный дом от Ufanet"](https://dom.ufanet.ru/) 
Используется открытое апи по упраленияб домофонами https://secretapi.ufanet.ru/ru/Intercom

## Возможности

- Авторизация по номеру договора и паролю
- Автоматическое обнаружение всех доступных домофонов
- Замок (lock) для открытия двери каждого домофона
- Датчик последнего вызова с историей звонков
- Изображение с превью последнего вызова
- Защита от повторного нажатия
- Поддержка нескольких домофонов в одном аккаунте

## Установка через HACS

1. Добавьте этот репозиторий в HACS как пользовательский репозиторий
2. Найдите "Hekus DoorPhone" в списке интеграций
3. Нажмите "Установить"
4. Перезагрузите Home Assistant

## Ручная установка

1. Скопируйте папку `hekus_doorphone` в директорию `custom_components` вашего Home Assistant
2. Перезагрузите Home Assistant
3. Добавьте интеграцию через интерфейс настроек

## Настройка

1. Перейдите в Настройки → Устройства и службы → Добавить интеграцию
2. Найдите "Hekus DoorPhone"
3. Введите номер договора и пароль от вашего аккаунта Ufanet
4. Интеграция автоматически обнаружит все доступные домофоны

## Сущности

Для каждого домофона создается:
- Замок «Door lock» — открытие двери, повторное открытие ограничено 8 секундами, сущность недоступна, если домофон заблокирован в аккаунте Ufanet

На отдельном устройстве «учётная запись Ufanet» (одно на договор) создаются:
- Датчик «Последний вызов» (`sensor`) — время последнего вызова и список последних звонков;
- Изображение «Превью последнего вызова» (`image`) — кадр с камеры домофона в момент последнего звонка.

## История вызовов

API Ufanet отдаёт историю вызовов по всему договору (`api/v1/skuds/call-history/`),
поэтому история не делится по домофонам: к какому подъезду относится звонок, видно
по атрибутам `address`, `porch`, `flat`, `camera_number`.

История опрашивается отдельным координатором раз в 60 секунд
(`CALL_HISTORY_SCAN_INTERVAL` в `const.py`). Если эндпоинт истории недоступен,
интеграция продолжает работать: замки открываются, а опрос истории повторяется
по расписанию. Пока истории нет, датчик последнего вызова и превью показываются
недоступными.

**Важно:** из-за опроса история обновляется с задержкой до 60 секунд, поэтому
сущности показывают состоявшийся звонок, но не подходят для мгновенной реакции
(открыть дверь или отправить push до того, как гость ушёл). Для таких сценариев
нужен сервис с push-уведомлениями от Ufanet — интеграция его не заменяет.

### Датчик «Последний вызов»

Состояние — время последнего вызова (`device_class: timestamp`).

Атрибуты:

- `calls_count` — сколько всего вызовов в истории Ufanet;
- `recording_url` и `preview_url` — ссылки на запись и превью последнего вызова;
- `calls` — до 10 последних вызовов (см. `CALL_HISTORY_PAGE_SIZE`), каждый со
  своими `uuid`, `called_at`, `address`, `porch`, `flat`, `house_id`,
  `camera_number`, `skud_mac`, `timezone`, `recording_url`, `preview_url`.

Список `calls` намеренно не пишется в историю Home Assistant (`recorder`):
он нужен для шаблонов и карточек, а не для статистики. Ссылки на запись и превью
запрашиваются один раз на вызов (запись появляется через несколько секунд после
звонка, поэтому неудачные попытки повторяются), а сами ссылки — временные.

### Изображение «Превью последнего вызова»

Состояние — время последнего вызова (`image_last_updated`), поэтому при новом
звонке карточка в интерфейсе сама перезапрашивает картинку. Кадр — то самое
превью, ссылка на которое есть в атрибуте `preview_url` датчика: интеграция
скачивает его один раз на вызов и держит в памяти, потому что ссылка временная,
а превью конкретного звонка не меняется. Живого потока и записи у изображения
нет — это статичный кадр момента звонка, `camera.play_stream` к нему неприменим.

Пример карточки:

```yaml
type: picture-entity
entity: image.domofon_ufanet_dogovor_1_prevju_poslednego_vyzova
name: Последний вызов
show_name: true
show_state: false
```

Если превью не удалось скачать (ссылка устарела или сеть недоступна), Home Assistant
покажет ошибку загрузки картинки, а повторная попытка произойдёт не раньше чем через
30 секунд (`CALL_PREVIEW_RETRY_SECONDS` в `const.py`). Скачивание ограничено
таймаутом 8 секунд и размером 8 МиБ, чтобы не блокировать интерфейс.

Пример карточки со списком последних звонков:

```yaml
type: markdown
content: |
  {% for call in state_attr('sensor.domofon_ufanet_dogovor_1_posledniy_vyzov', 'calls') or [] %}
  - {{ call.called_at }} — {{ call.address }}, кв. {{ call.flat }}
  {% endfor %}
```

Пример автоматизации: уведомление о новом вызове по изменению датчика
(с учётом задержки опроса — до 60 секунд):

```yaml
automation:
  - alias: "Новый вызов в домофон"
    triggers:
      - trigger: state
        entity_id: sensor.domofon_ufanet_dogovor_1_posledniy_vyzov
    conditions:
      - condition: template
        value_template: "{{ trigger.to_state.state not in ['unknown', 'unavailable'] }}"
    actions:
      - action: notify.mobile_app_phone
        data:
          title: Звонок в домофон
          message: >-
            {{ state_attr(trigger.entity_id, 'calls')[0].address }},
            подъезд {{ state_attr(trigger.entity_id, 'calls')[0].porch }},
            кв. {{ state_attr(trigger.entity_id, 'calls')[0].flat }}
          data:
            image: "{{ state_attr(trigger.entity_id, 'preview_url') }}"
```

Идентификаторы сущностей зависят от названия договора: точные `entity_id` смотрите
в Настройки → Устройства и службы → сущности интеграции.

## Поддерживаемые домофоны

Интеграция работает с домофонами, поддерживаемыми сервисом Ufanet:
- Домофоны в подъездах
- Калиточные домофоны
- Другие устройства, доступные в личном кабинете Ufanet

## Диагностика

В карточке интеграции (Настройки → Устройства и службы → Hekus DoorPhone) доступна
выгрузка диагностики: список домофонов из API, состояние координатора и интервал
опроса, а также последние вызовы из истории. Пароль в выгрузку не попадает.

## Камеры видеонаблюдения (API)

Клиент API умеет получать камеры аккаунта: `UfanetIntercomAPI.get_cameras()` возвращает
список моделей `Camera`. Помимо полей ответа (`number`, `title`, `address`, `servers`,
`token_l`, `token_r`, `type`, `inactivity_period`) у модели есть вычисляемые свойства:

- `rtsp_url` — ссылка на живой поток
  `rtsp://{servers.domain}/{number}?token={token_l}&tracks=v1a1`
  (`tracks=v1a1` запрашивает у Flussonic видео- и аудиодорожку);
- `screenshot_url` — актуальный снапшот
  `https://{servers.screenshot_domain}/api/v0/screenshots/{number}~600.jpg?token={token_l}`.

Что важно при использовании ссылок:

- `token_l` — живой JWT камеры с ограниченным сроком жизни, поэтому ссылку нужно
  периодически обновлять повторным `get_cameras()`; частые запросы списка камер Ufanet
  ограничивает (HTTP 429), так что обновлять стоит не чаще раза в несколько минут;
- `token_r` — токен записи (архив), для живого RTSP-потока он не используется;
- часть полей у отдельных камер может быть `null` (`servers`, `token_r`, координаты,
  `title`, `address`), поэтому оба свойства возвращают `None`, если ссылку построить нельзя.

Сущностей `camera` интеграция не создаёт — это только слой доступа к API.
Превью последнего вызова домофона — отдельная сущность `image`, описанная
в разделе «История вызовов»; живого потока она не даёт.

## Проверка API без Home Assistant

Скрипт `scripts/ufanet_api_example.py` авторизуется тем же способом, что и интеграция,
и печатает список камер видеонаблюдения с RTSP-ссылками и последние вызовы домофона
со ссылками на превью и запись.
Установленный Home Assistant не нужен — достаточно зависимостей клиента:

```powershell
pip install aiohttp pydantic
```

Учётные данные берутся из переменных окружения:

```powershell
$env:UFANET_CONTRACT="номер договора"
$env:UFANET_PASSWORD="пароль"
python scripts/ufanet_api_example.py
```
